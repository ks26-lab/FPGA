# V_SPACE Troubleshooting & Diagnostic Guide

This guide covers common issues, root causes, and verified solutions across hardware setup, Vivado synthesis, Linux runtime execution, and testbench parity.

---

## 1. Hardware Connection & Programming Issues

### Problem 1.1: Board Not Detected in Vivado Hardware Manager
- **Symptoms:** Vivado reports `No targets found` or `Cannot connect to server`.
- **Causes & Solutions:**
  1. **Cable Check:** Ensure the micro-USB cable is connected to the dedicated **JTAG** port, not solely to the UART port. Verify the cable supports data transfer (some cheap cables are charge-only).
  2. **Driver Installation:** On Windows, verify **Xilinx Cable USB** or **Digilent USB Device** appears in Device Manager without yellow exclamation marks. Re-run Vivado cable driver installer:
     ```cmd
     <Vivado_Install_Dir>\data\xicom\cable_drivers\nt64\install_drivers_wrapper.bat
     ```
  3. **Power Switch:** Ensure the board's power switch is ON and the power LED is brightly lit.

### Problem 1.2: Green DONE LED Does Not Illuminate After Programming
- **Symptoms:** Vivado reports programming completed, but the green `DONE` LED remains off, and PL logic is inert.
- **Causes & Solutions:**
  1. **Clock Configuration:** Ensure the top-level design is connected to a valid clock. In Zynq, the PL clock `FCLK_CLK0` is generated by the PS. If the PS is in reset or uninitialized, PL clocks will not toggle.
  2. **Part Number Mismatch:** Verify the synthesis target is strictly `xc7z010clg400-1`. Programming a bitstream targeting a different package will fail silent CRC checks.

## 2. Zynq Linux Runtime & Communication Issues

### Problem 2.1: `mmap: Operation not permitted` or `/dev/mem` Access Failure
- **Symptoms:**
  ```text
  FATAL: ERROR: FPGA hardware interface unavailable.
  Failed to memory-map AXI address 0x43C00000.
  ```
- **Causes & Solutions:**
  1. **Root Privileges:** The process must be executed as root. Prepend `sudo`:
     ```bash
     sudo python3 main.py --hw
     ```
  2. **Strict Devmem Protection:** Modern Linux kernels block access to physical RAM above the low-mem limit by default. Add `iomem=relaxed` to U-Boot bootargs:
     ```text
     setenv bootargs 'console=ttyPS0,115200 root=/dev/mmcblk0p2 rw earlyprintk iomem=relaxed'
     saveenv
     boot
     ```

### Problem 2.2: PuTTY Console Displays Garbage Characters
- **Symptoms:** Unreadable or scrambled text (`?`) on serial terminal.
- **Causes & Solutions:**
  1. **Baud Rate Mismatch:** Set PuTTY baud rate to **115200**.
  2. **Framing Settings:** Ensure Data bits = `8`, Stop bits = `1`, Parity = `None`, Flow control = `None`.

### Problem 2.3: ModuleNotFoundError or Import Collision in Python
- **Symptoms:** `ModuleNotFoundError: No module named 'python.core'` or `No module named 'hardware'`.
- **Causes & Solutions:**
  1. Run scripts from the repository root directory:
     ```bash
     cd /home/root/v_space
     python3 main.py
     ```
  2. Or set `PYTHONPATH`:
     ```bash
     export PYTHONPATH=.
     ```

## 3. Vivado Synthesis & Implementation Issues

### Problem 3.1: Timing Violation (Negative Slack / WNS < 0 ns)
- **Symptoms:** Implementation completes with critical warning `Timing constraints are not met`.
- **Causes & Solutions:**
  1. **Clock Constraint:** Verify `edge_zynq_z7010.xdc` defines a 50 MHz clock (`20.0 ns` period):
     ```tcl
     create_clock -period 20.000 -name sys_clk_pin -waveform {0.000 10.000} [get_ports s_axi_aclk]
     ```
  2. **Pipelining:** Complex multi-stage calculations (e.g., 8-channel squared distance in Mars Habitat, or incident angle vector multiplication in Solar Gimbal) must utilize the existing pipeline registers rather than single-cycle combinational cascades.

### Problem 3.2: Synthesis Fails Due to Missing Headers or Files
- **Symptoms:** `Could not find include file underwater_fixed_point_pkg.vh`.
- **Causes & Solutions:**
  1. Ensure both `.v` and `.vh` files are added to design sources (`add_files -norecurse [glob -nocomplain "./*.vh"]`).

## 4. Test Suite & Parity Validation Issues

### Problem 4.1: Parity Discrepancy Between RTL Testbench and Python Emulator
- **Symptoms:** `test_rtl_emulator_parity.py` fails assertion on tick count or register value.
- **Causes & Solutions:**
  1. **Fixed-Point Scaling:** Verify scaling constants match between Verilog and Python:
     - Depth: `1 unit = 0.1 m` (e.g., 500 = 50.0m).
     - Velocity: `1 unit = 0.1 m/s`.
     - Solar Angles: `1 unit = 0.1°` (0 to 3600).
     - Traffic Positions: `1 unit = 1.0 m` (0 to 120m).
  2. **Autonomous Clock Interference:** When running automated unit tests, ensure the emulator's autonomous background thread is paused (`enable_autonomous_clock=False`) so manual stepping (`emulator.tick()`) controls the sequence.
